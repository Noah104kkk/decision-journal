# 設計メモ

判断ログが「何を計算し、何を計算しないか」の記録です。

## 1. 順序を仕組みで守る
「AIの提案を見る前に、自分の考えを固める」ことが目的です。意志に頼らず、画面の制約で実現します。

| 段階 | 変更できるか | 理由 |
|---|---|---|
| 基準・採点 | ロックまで | ロック後に変えると、結果に合わせた後付けが可能になる |
| 直感の選択 | ロックまで | 同上 |
| AI・他者の提案 | **ロック後だけ入力可** | 提案に引きずられる前に自分の考えを固めるため |
| 決定（選択・自信度%） | 決定まで。以後不変 | 後から「そう思っていた」と言えなくする |
| 振り返り | 期限以降に1回 | 結果が見えてから記録するため |

## 2. 計算
### 加重スコア（基準）
選択肢 *i* のスコア = Σ(重み_j × 点数_ij) / Σ(重み_j)。最大が1つなら基準の推し、**同点なら「同点」とし、無理に選ばない**。

### ウィルソン区間（成功率の不確かさ）
成功 *k* 件／*n* 件、*p* = k/n、*z* = 1.96 のとき

```
centre = p + z²/(2n)
margin = z · sqrt( p(1−p)/n + z²/(4n²) )
区間   = (centre ∓ margin) / (1 + z²/n)
```
件数が少なくても 0% や 100% に張り付かず、*n* = 0 は [0, 1]。2つの区間が重なる時は「偶然の範囲かもしれません」と表示し、差を断定しません。

### Brierスコア（自信度の精度）
`Brier = 平均( (自信度 − 結果)² )`、結果は成功 1／失敗 0。0に近いほど良い。
比較用に、「常に平均の成功率を答える」場合のスコア（`brierBase`）も出し、**それより悪ければ**、自信度に情報が乗っていないと注意します。自信度1〜99%の判断だけを対象にします。

### 較正グラフ
自信度を [〜49, 50s, 60s, 70s, 80s, 90〜] に分け、各区間の平均自信度（横）と実際の成功率（縦）を点で描きます。点の大きさは件数。対角線に近いほど較正が合っています。

## 3. 計算しないこと（反事実）
結果が分かるのは **実際に選んだ選択肢だけ** です。選ばなかった選択肢がどうなったかは観測できません。したがって「AIに従った時の成功率が高い」は「AIが正しかった」証明ではなく、「AIに従う判断を、自分が選んだ時の結果」にすぎません（選び方に偏りがある）。画面にも同じ注意を常時表示しています。
振り返り5件未満の間は「参考程度」と明示します。

## 4. 入力の上限（`store.js` の `LIMITS`）
| 項目 | 上限 |
|---|---|
| 判断の件数 | 500 |
| 選択肢 / 基準 | 5 / 6 |
| 問い / 背景 | 120 / 500 文字 |
| 選択肢名 / 基準名 / 出典 | 60 / 40 / 40 文字 |
| メモ・学び | 300 文字 |
| 読み込みファイル | 2 MB |

制御文字は除去し、IDは `^[A-Za-z0-9-]{1,64}$` のみ許可。日付は実在を確認します。保存・インポート・復号の結果は、すべて同じ `sanitize` を通ります。

## 5. 暗号化書き出し
AES-256-GCM。鍵は PBKDF2-SHA256（60万回、許容範囲は10万〜200万）、salt 16B、iv 12B。パスフレーズは保存しません。読み込み時は、反復回数・salt/ivの長さ・形式を **計算の前に** 検査し、悪意あるファイルで画面が固まらないようにします。復号失敗は、パスフレーズ違いと改ざんを区別しない汎用エラーです。

## 6. 既知の限界
- 件数が少ないと、区間が広く何も言えないことが多い（仕様どおり）
- 結果は良い／良くないの2値。満足度の段階は今後の課題
- ブラウザの localStorage に保存されるため、端末・ブラウザをまたいで同期しない（暗号化書き出しで持ち運ぶ）
